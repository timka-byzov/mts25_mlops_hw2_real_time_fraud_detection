# Скоринг транзакций

Сервис читает транзакции из Kafka, считает вероятность фрода и пишет результат
в топик `scores`. Отдельный consumer сохраняет результаты в PostgreSQL.
В третьей домашке добавлено переобучение через Airflow.

## Запуск

Нужны Docker с Compose и `train.csv` из
[датасета teta-ml-1-2025](https://www.kaggle.com/competitions/teta-ml-1-2025/data).
Положить файл в `data/train.csv`, затем выполнить:

```bash
docker compose up --build -d
```

На Mac с Podman вместо `docker compose` используется `podman compose`.
Датасет в репозиторий не входит.

Адреса:

- Streamlit: http://localhost:8501
- Kafka UI: http://localhost:8080
- Airflow: http://localhost:8081

Логин в Airflow: `admin`. Пароль можно получить после запуска:

```bash
docker compose exec airflow cat /opt/airflow/standalone_admin_password.txt
```

## Переобучение

В Airflow есть два DAG. Сначала они выключены.

`fraud_retraining` запускается раз в 5 минут. В нём три задачи:
подготовка выборки, обучение CatBoost на CPU, публикация файла модели.
Для первого запуска нужно включить DAG в UI и нажать Trigger DAG.
Зелёный статус `success` означает, что все три задачи завершились.
Текущую опубликованную версию можно посмотреть командой:

```bash
docker compose exec airflow cat /opt/models/current.json
```

`add_training_month` раз в 10 минут добавляет новый месяц в размеченную
таблицу `training_transactions`. Он копирует до 5000 строк последнего
месяца и переносит дату на следующий календарный месяц. Его тоже нужно
включить в UI; для проверки можно запустить вручную.
После добавления месяца следующий запуск `fraud_retraining` обучит новую модель.
Догонять пропущенные запуски оба DAG не будут (`catchup=False`).

Начальная витрина собирается из первых 5000 строк каждого месяца `train.csv`.
Глубина истории составляет 36 месяцев. В обучении используется окно из
трёх месяцев: первые два идут в train, последний в test.
После публикации окно сдвигается на один месяц. Если нового месяца ещё нет,
переобучение пропускается.

Препроцессинг общий для обучения и скоринга: логарифм суммы и населения,
расстояние до продавца, час, день недели, месяц и признак выходного.
Категории передаются CatBoost строками. Обучение занимает 50 итераций;
accuracy и logloss на последнем месяце записываются в лог и `current.json`.

Повтор задачи использует тот же выбранный месяц. Он записан в рабочем
каталоге запуска. Указатель обученного месяца находится в `current.json`
и обновляется после сохранения модели. Добавление данных тоже запоминает
`run_id`, поэтому повтор после ошибки не добавляет тот же батч второй раз.

Размер батча, глубину истории и окно можно задать через `BATCH_SIZE`,
`HISTORY_MONTHS` и `WINDOW_MONTHS` перед запуском Compose.
Окно должно содержать минимум два месяца и помещаться в глубину истории.

## Проверка скоринга

В Streamlit нажать «Отправить пример» или загрузить небольшой CSV
с транзакциями формата `test.csv`. В Kafka UI открыть топик `scores`.
В каждом результате есть поля:

```json
{
  "transaction_id": "example-id",
  "score": 0.12,
  "fraud_flag": 0,
  "model_version": "2020-03-..."
}
```

`model_version` должен совпадать с `version` в `current.json`.
До первого переобучения будет `baseline`.
После нового запуска DAG отправить ещё один пример: версия должна измениться
без перезапуска контейнера `fraud_detector`.
Модели находятся в общем томе `model-data`, скоринг читает его без записи.
Порог фрода по умолчанию равен 0.98, его задаёт `FRAUD_THRESHOLD`.

Раздел «Результаты скоринга» в Streamlit показывает десять последних
фродовых транзакций и гистограмму последних ста скоров из PostgreSQL.

## Файлы

- `airflow/dags/`: графы задач.
- `airflow/jobs/`: работа с данными, обучение и публикация модели.
- `fraud_detector/src/features.py`: признаки новой модели.
- `fraud_detector/src/scorer.py`: скоринг и загрузка опубликованной модели.
- `score_writer/`: запись результатов в PostgreSQL.
- `interface/`: отправка транзакций и просмотр результатов.

Проверки Python-кода:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
pytest -q
```

Остановка с сохранением данных и моделей:

```bash
docker compose down
```

Основа проекта: [семинарский сервис скоринга](https://github.com/vladik-pwnz/hw2-kafka).
